Data buku yang sudah tersimpan kadang perlu diperbaiki, misalnya karena nama penulisnya salah ketik. Materi ini menambahkan halaman ubah buku dan memakai ulang BukuRequest dari materi sebelumnya sehingga aturan validasinya tidak perlu ditulis dua kali.

Rute Ubah dan Simpan Perubahan

Tambahkan dua rute berikut di routes/web.php:

Route::get('/buku/{buku}/ubah', [BukuController::class, 'edit'])->name('buku.edit');
Route::put('/buku/{buku}', [BukuController::class, 'update'])->name('buku.update');

Rute pertama menampilkan formulir berisi data lama. Rute kedua menerima perubahannya dengan permintaan PUT, metode HTTP yang lazim dipakai untuk memperbarui data. Keduanya memakai route model binding seperti halaman detail sehingga buku yang tidak ada otomatis menghasilkan halaman 404.

Satu Formulir untuk Tambah dan Ubah

Isian formulir ubah sama persis dengan formulir tambah. Daripada menyalinnya, pindahkan isian itu ke partial resources/views/buku/_form.blade.php:

<p>
    <label for="judul">Judul</label>
    <input type="text" id="judul" name="judul" value="{{ old('judul', $buku->judul) }}">
    @error('judul') <small>{{ $message }}</small> @enderror
</p>
<p>
    <label for="penulis">Penulis</label>
    <input type="text" id="penulis" name="penulis" value="{{ old('penulis', $buku->penulis) }}">
    @error('penulis') <small>{{ $message }}</small> @enderror
</p>
<p>
    <label for="tahun_terbit">Tahun Terbit</label>
    <input type="number" id="tahun_terbit" name="tahun_terbit" value="{{ old('tahun_terbit', $buku->tahun_terbit) }}">
    @error('tahun_terbit') <small>{{ $message }}</small> @enderror
</p>

<button type="submit">Simpan</button>

Argumen kedua old() adalah nilai cadangan. Saat formulir pertama kali dibuka, isian berisi data buku. Saat validasi gagal, isian berisi ketikan terakhir pengunjung.

Formulir tambah kini cukup memanggil partial tersebut. Ganti isi <form> di create.blade.php:

<form method="POST" action="{{ route('buku.store') }}">
    @csrf
    @include('buku._form')
</form>

Formulir tambah juga membutuhkan variabel $buku, jadi kirim model kosong dari method create():

public function create()
{
    return view('buku.create', ['buku' => new Buku]);
}

Halaman Ubah

Buat resources/views/buku/edit.blade.php:

@extends('layouts.app')

@section('judul', 'Ubah Buku')

@section('konten')
    <h1>Ubah Buku</h1>

    <form method="POST" action="{{ route('buku.update', $buku) }}">
        @csrf
        @method('PUT')
        @include('buku._form')
    </form>
@endsection

Formulir HTML hanya mengenal GET dan POST. Direktif @method('PUT') menyisipkan isian tersembunyi _method sehingga Laravel memperlakukan kiriman POST ini sebagai PUT dan mencocokkannya dengan rute buku.update. Teknik ini disebut method spoofing.

Menyimpan Perubahan

Tambahkan method edit() dan update() di BukuController:

public function edit(Buku $buku)
{
    return view('buku.edit', compact('buku'));
}

public function update(BukuRequest $request, Buku $buku)
{
    $buku->update($request->validated());

    return redirect()->route('buku.show', $buku)->with('status', 'Buku berhasil diperbarui.');
}

update() mengisi kolom yang tercantum di #[Fillable], lalu menyimpannya. Eloquent hanya menulis kolom yang nilainya benar-benar berubah dan ikut memperbarui updated_at. Bila tidak ada yang berubah, Eloquent sama sekali tidak mengirim query ke basis data.

Terakhir, tambahkan tautan ke halaman ubah di show.blade.php:

<p><a href="{{ route('buku.edit', $buku) }}">Ubah data buku</a></p>

Buka detail salah satu buku, klik tautan itu, ubah tahun terbitnya, lalu simpan. Anda akan kembali ke halaman detail dengan pesan "Buku berhasil diperbarui." dan data yang sudah berubah.

Bila Kelak Ada Kolom Unik

Misalkan tabel buku kelak memiliki kolom International Standard Book Number (ISBN) yang harus unik. Aturan unique biasa akan menolak perubahan yang tidak mengganti ISBN karena nilai itu sudah dipakai, yaitu oleh buku itu sendiri. Kecualikan buku yang sedang diubah dengan Rule::unique('buku', 'isbn')->ignore($this->route('buku')).

Contoh ini sekaligus menunjukkan manfaat memisahkan validasi ke Form Request: aturan yang berubah cukup diperbaiki di satu tempat. Kini data buku bisa ditambah, dilihat, dan diubah. Pada materi terakhir, kita akan menghapus data dengan aman dan merapikan semua rute menjadi satu baris.
