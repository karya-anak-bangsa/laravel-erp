Sebagian besar logika program berada di dalam fungsi sehingga tipe pada fungsi memberi manfaat paling besar. Materi terakhir seri ini membahas tipe parameter dan nilai kembalian, union type bagi nilai yang bisa berupa beberapa tipe, serta narrowing untuk memastikan tipe yang sedang ditangani. Tulis contohnya di berkas baru src/kasir.ts.

Tipe Parameter dan Nilai Kembalian

Setiap parameter diberi anotasi, sedangkan tipe nilai kembalian ditulis setelah tanda kurung tutup:

function hitungTagihan(harga: number, jumlah: number, potongan = 0): number {
  return harga * jumlah - potongan;
}

function sapaPelanggan(nama?: string): string {
  return `Terima kasih, ${nama ?? 'Pelanggan'}!`;
}

const cetakStruk = (total: number): void => {
  console.log(`Total bayar: Rp${total}`);
};

cetakStruk(hitungTagihan(75000, 2, 10000)); // Total bayar: Rp140000
console.log(sapaPelanggan()); // Terima kasih, Pelanggan!

Parameter potongan memiliki nilai bawaan 0 sehingga tipenya disimpulkan sebagai number dan boleh tidak diisi. Tanda ? membuat nama opsional; nilainya undefined bila tidak diisi. Tipe void menandakan fungsi tidak mengembalikan nilai. Seperti terlihat pada cetakStruk, arrow function diberi tipe dengan cara yang sama.

Nilai dengan Beberapa Kemungkinan Tipe

Union type ditulis dengan tanda | dan berarti nilai boleh berupa salah satu dari tipe yang disebutkan. Gabungan tipe literal sangat berguna bagi daftar pilihan yang tetap:

type StatusPesanan = 'menunggu' | 'dikirim' | 'selesai';

let status: StatusPesanan = 'menunggu';
status = 'dikirim';
status = 'batal'; // galat

TypeScript menolak 'batal' karena nilai itu tidak ada di daftar. Editor juga menyarankan ketiga pilihan yang sah saat Anda mengetik tanda kutip.

Mempersempit Tipe dengan Narrowing

Nilai bertipe number | string hanya boleh dipakai dengan cara yang sah bagi kedua tipe sekaligus. Akibatnya, kode.toUpperCase() ditolak karena angka tidak memiliki method itu. Periksa tipenya dulu dengan typeof:

function formatKodePesanan(kode: number | string): string {
  if (typeof kode === 'number') {
    return `INV-${kode.toString().padStart(5, '0')}`;
  }

  return kode.toUpperCase();
}

console.log(formatKodePesanan(42)); // INV-00042
console.log(formatKodePesanan('inv-00077')); // INV-00077

Di dalam blok if, TypeScript tahu bahwa kode pasti angka. Setelah blok itu, satu-satunya kemungkinan yang tersisa adalah string. Proses mempersempit tipe berdasarkan pemeriksaan seperti ini disebut narrowing. TypeScript juga mengenali pemeriksaan lain, antara lain === null, instanceof, dan operator in.

Membedakan Objek dengan Properti Penanda

Teknik narrowing paling terasa manfaatnya saat menangani beberapa bentuk objek. Beri setiap bentuk sebuah properti penanda bernilai literal, misalnya metode:

type Pembayaran =
  | { metode: 'tunai'; uangDiterima: number }
  | { metode: 'transfer'; namaBank: string };

function jelaskanPembayaran(pembayaran: Pembayaran, total: number): string {
  switch (pembayaran.metode) {
    case 'tunai':
      return `Kembalian: Rp${pembayaran.uangDiterima - total}`;
    case 'transfer':
      return `Dibayar lewat transfer ${pembayaran.namaBank}`;
  }
}

console.log(jelaskanPembayaran({ metode: 'tunai', uangDiterima: 200000 }, 140000)); // Kembalian: Rp60000

Di setiap case, TypeScript hanya mengizinkan properti milik bentuk yang sesuai, jadi namaBank tidak bisa dibaca di cabang 'tunai'. Bila kelak Anda menambah metode baru, misalnya 'dompet-digital', kompilator mengingatkan bahwa fungsi ini belum menangani metode tersebut. Pola ini dikenal sebagai discriminated union.
