Aplikasi nyata sering membutuhkan beberapa variasi tipe dari data yang sama: ringkasan untuk daftar, data baru tanpa id, atau perubahan sebagian. Menulis ulang setiap variasi secara manual berisiko: saat satu tipe berubah, tipe lain mudah terlupa. TypeScript menyediakan utility types, yaitu tipe generic bawaan yang membentuk tipe baru dari tipe yang sudah ada.

Tipe Dasar Pengguna

Buat berkas src/pengguna.ts berisi tipe utama katalog:

export interface Pengguna {
  id: number;
  name: string;
  email: string;
  website: string;
}

Nama propertinya mengikuti data JSONPlaceholder agar cocok saat data diambil di materi terakhir. Data aslinya juga memuat properti lain seperti address dan company, tetapi kita cukup mencatat yang dibutuhkan. Tambahkan semua tipe berikutnya di berkas yang sama.

Memilih dan Membuang Properti

Pick mengambil sebagian properti, sedangkan Omit membuang properti tertentu:

export type RingkasanPengguna = Pick<Pengguna, 'id' | 'name' | 'email'>;

export type PenggunaBaru = Omit<Pengguna, 'id'>;

Tipe RingkasanPengguna cocok untuk daftar singkat yang tidak memerlukan website. Adapun PenggunaBaru cocok untuk formulir tambah data karena id biasanya diberikan oleh server. TypeScript juga memeriksa nama properti di antara tanda kutip, jadi salah ketik seperti 'nama' langsung ditolak. Kedua tipe ini selalu mengikuti Pengguna: bila tipe salah satu propertinya berubah, RingkasanPengguna dan PenggunaBaru ikut berubah tanpa perlu disunting.

Membuat Semua Properti Opsional

Partial mengubah semua properti menjadi opsional. Tipe ini cocok untuk data perubahan yang hanya berisi bagian yang diganti:

export type PerubahanPengguna = Partial<PenggunaBaru>;

export function perbaruiPengguna(pengguna: Pengguna, perubahan: PerubahanPengguna): Pengguna {
  return { ...pengguna, ...perubahan };
}

Operator spread (...) menyalin semua properti pengguna, lalu menimpanya dengan isi perubahan. Hasilnya berupa objek baru, sedangkan objek lama tidak berubah. Tipe PerubahanPengguna disusun dari PenggunaBaru yang tidak memuat id sehingga id tidak bisa ikut diubah lewat fungsi ini. Beberapa utility types memang bisa digabung seperti ini.

Memetakan Kunci ke Nilai

Record membuat tipe objek dari daftar kunci dan tipe nilainya. Contoh berikut menyiapkan label kolom untuk ringkasan pengguna:

export const labelKolom: Record<keyof RingkasanPengguna, string> = {
  id: 'No.',
  name: 'Nama',
  email: 'Email',
};

Operator keyof menghasilkan gabungan nama properti, yaitu 'id' | 'name' | 'email'. Bila salah satu label terlewat, TypeScript langsung menolak objek ini. Saat RingkasanPengguna kelak bertambah properti, kompilator mengingatkan Anda untuk menambah labelnya juga.

Melindungi Data dari Perubahan

Readonly membuat semua properti hanya bisa dibaca. Coba dengan mengganti isi src/main.ts:

import './style.css';
import { labelKolom, perbaruiPengguna, type Pengguna } from './pengguna.ts';

const contoh: Readonly<Pengguna> = {
  id: 1,
  name: 'Leanne Graham',
  email: 'Sincere@april.biz',
  website: 'hildegard.org',
};

contoh.website = 'leanne.dev'; // galat

const diperbarui = perbaruiPengguna(contoh, { website: 'leanne.dev' });

console.log(labelKolom.name, diperbarui.name); // Nama Leanne Graham
console.log(diperbarui.website); // leanne.dev

Kata type di dalam import menandakan bahwa Pengguna hanya berupa tipe. Opsi verbatimModuleSyntax yang aktif di templat Vite mewajibkan penanda ini. Alih-alih mengubah contoh secara langsung, perbaruiPengguna() membuat objek baru. Hapus baris bertanda galat setelah mencobanya. Ingat juga bahwa Readonly bersifat dangkal: objek di dalam properti tetap bisa diubah. Gunakan readonly Pengguna[] pada array agar push() ikut ditolak.

Pada materi berikutnya, kita akan mengambil data pengguna sungguhan dari API dan memastikan bentuknya sesuai dengan tipe Pengguna.
