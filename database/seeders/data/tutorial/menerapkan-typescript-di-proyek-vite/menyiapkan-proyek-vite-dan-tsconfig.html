Seri ini membangun katalog pengguna sederhana yang mengambil data dari JSONPlaceholder, layanan Application Programming Interface (API) tiruan yang gratis untuk latihan. Anda cukup memahami dasar JavaScript dan HTML serta anotasi tipe, interface, dan union type seperti yang dibahas di tutorial Dasar-Dasar TypeScript. Pastikan juga Node.js sudah terpasang.

Materi pertama ini menyiapkan proyek dengan Vite, mengenalkan struktur berkasnya, dan menjelaskan opsi penting di tsconfig.json.

Membuat Proyek Baru

Vite adalah alat bantu pengembangan web yang menyediakan server lokal yang cepat sekaligus menggabungkan kode menjadi berkas siap produksi. Buat proyek baru dengan templat vanilla-ts, yaitu TypeScript tanpa framework seperti React atau Vue:

npm create vite@latest katalog-pengguna -- --template vanilla-ts
cd katalog-pengguna
npm install
npm run dev

Tanda -- meneruskan opsi --template ke pembuat proyek Vite. Bila pembuat proyek menanyakan apakah dependensi ingin langsung dipasang dan dijalankan, pilih No agar ketiga perintah berikutnya bisa Anda jalankan sendiri. Perintah npm run dev menyalakan server pengembangan dan menampilkan alamatnya di terminal, biasanya http://localhost:5173. Buka alamat itu di peramban untuk melihat halaman contoh.

Mengenal Struktur Proyek

Isi folder proyek bisa sedikit berbeda antarversi templat, tetapi bagian utamanya sama:

  • index.html adalah halaman utama yang memuat src/main.ts lewat tag <script type="module">.

  • src/main.ts adalah titik awal kode TypeScript. Folder src juga berisi CSS dan beberapa berkas contoh.

  • public berisi berkas statis yang disalin apa adanya, misalnya ikon situs.

  • package.json mencatat paket beserta perintah dev, build, dan preview.

  • tsconfig.json berisi pengaturan TypeScript.

Peramban tidak bisa menjalankan TypeScript. Saat peramban meminta src/main.ts, Vite membuang anotasi tipenya, lalu mengirim JavaScript hasilnya.

Opsi Penting di Pengaturan TypeScript

Buka tsconfig.json. Templat Vite sudah mengisinya dengan banyak opsi yang nilainya bisa berubah antarversi, jadi kenali saja opsi yang paling berpengaruh:

  • strict mengaktifkan sekumpulan pemeriksaan ketat, antara lain larangan tipe any tersirat dan pemeriksaan nilai null.

  • noEmit membuat tsc hanya memeriksa tipe tanpa menulis berkas JavaScript karena Vite yang menghasilkan berkas akhir.

  • lib yang memuat DOM membuat tipe seperti HTMLElement dan objek document dikenali.

  • moduleResolution bernilai bundler mencari berkas yang diimpor dengan cara yang sama seperti Vite.

  • noUnusedLocals dan noUnusedParameters menganggap variabel dan parameter yang tidak terpakai sebagai galat.

  • include menentukan folder yang diperiksa, yaitu src.

Bila strict belum tertulis, tambahkan opsi itu di dalam compilerOptions agar pemeriksaan ketat pasti aktif:

{
  "compilerOptions": {
    // opsi bawaan templat tetap dibiarkan
    "strict": true
  },
  "include": ["src"]
}

Vite Tidak Memeriksa Tipe

Ganti seluruh isi src/main.ts dengan kode berikut. Kode ini sengaja memuat kesalahan tipe:

import './style.css';

const judul: string = 404;
const app = document.querySelector('#app');

if (app) {
  app.innerHTML = `<h1>${judul}</h1>`;
}

Editor langsung memberi garis bawah merah pada judul, tetapi halaman di peramban tetap menampilkan angka 404. Vite hanya membuang tipe tanpa memeriksanya agar server pengembangan tetap cepat. Editor dan tsc yang bertugas memeriksa tipe. Perhatikan juga bahwa querySelector() mengembalikan null bila elemennya tidak ditemukan sehingga pemeriksaan if (app) wajib ada.

Membangun Versi Produksi

Jalankan perintah berikut di terminal lain atau setelah menghentikan server dengan Ctrl+C:

npm run build

Perintah ini menjalankan tsc, lalu vite build. Bagian kedua hanya berjalan bila tsc tidak menemukan galat, jadi kesalahan tadi menghentikan proses dengan pesan berikut:

src/main.ts:3:7 - error TS2322: Type 'number' is not assignable to type 'string'.

Ubah nilai judul menjadi 'Katalog Pengguna', lalu jalankan npm run build lagi. Kali ini Vite menulis hasil akhirnya di folder dist yang bisa Anda lihat dengan npm run preview. Dengan begitu, kode yang tipenya salah tidak akan lolos ke versi produksi.

Pada materi berikutnya, kita akan menulis fungsi yang bisa dipakai ulang untuk berbagai jenis data dengan generic.
