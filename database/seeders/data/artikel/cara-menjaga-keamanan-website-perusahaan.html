Banyak pemilik usaha baru sadar website-nya kebobolan ketika pelanggan bertanya mengapa hasil pencarian Google menampilkan halaman judi daring atas nama perusahaan mereka. Pada titik itu, kerusakan sudah terjadi: reputasi tercoreng, peringkat pencarian anjlok, dan pemulihannya memakan waktu serta biaya.

Kabar baiknya, Anda bisa mencegah sebagian besar serangan dengan menjalankan kebiasaan dasar secara konsisten. Panduan ini menyasar pemilik bisnis dan tim IT kecil. Isinya mencakup pembaruan rutin, HTTPS, pengamanan akun admin, pencadangan, perlindungan tambahan, dan pemantauan.

Perbarui CMS, Plugin, dan Framework secara Rutin

Banyak peretasan memanfaatkan celah yang tambalannya sebenarnya sudah tersedia dari pengembang, tetapi pemilik website belum memasang pembaruan tersebut. Website WordPress dengan plugin dan tema yang jarang mendapat pembaruan adalah contoh yang paling umum. Hal yang sama berlaku untuk aplikasi buatan sendiri yang memakai framework seperti Laravel, beserta paket Composer dan npm di dalamnya.

Jadwalkan pemeriksaan pembaruan setidaknya sekali seminggu, uji pembaruan dulu di salinan website (staging) bila memungkinkan, lalu hapus plugin dan tema yang tidak terpakai. Hindari juga tema atau plugin berbayar versi bajakan (nulled) karena versi ini sering sudah mengandung kode jahat sejak awal.

Jika Anda pengembang, jalankan composer audit dan npm audit secara rutin. Kedua perintah ini memeriksa apakah paket di proyek Anda memiliki kerentanan yang sudah terungkap. Hasilnya menunjukkan paket mana yang perlu segera Anda perbarui.

Pasang HTTPS dan Rapikan Konfigurasi Server

HTTPS mengenkripsi data antara pengunjung dan server, termasuk isian formulir dan data login admin. Kini Anda bisa mendapatkan sertifikat SSL/TLS gratis dari Let's Encrypt. Banyak penyedia hosting juga sudah menyediakannya dalam beberapa klik. Pastikan server mengalihkan semua alamat HTTP ke HTTPS.

Setelah itu, rapikan konfigurasi. Matikan mode debug di server produksi (misalnya APP_DEBUG=false pada Laravel) agar pesan galat tidak membocorkan detail sistem. Tambahkan header keamanan seperti HSTS dan Content-Security-Policy. Pastikan juga pengunjung tidak bisa mengunduh berkas cadangan atau berkas .env.

Kunci Pintu Admin: Password, 2FA, dan Hak Akses Minimum

Halaman login admin adalah pintu yang paling sering menjadi sasaran penyerang. Mereka biasanya menebak password secara otomatis. Perkuat pintu ini dengan kebiasaan berikut.

  • Gunakan password panjang dan unik untuk setiap akun admin, simpan di pengelola password, dan jangan memakai satu akun bersama-sama.

  • Aktifkan autentikasi dua faktor (2FA) untuk admin website, panel hosting, dan email domain.

  • Terapkan prinsip hak akses minimum: penulis konten cukup mendapat akses editor, bukan administrator.

  • Hapus akun karyawan atau vendor yang sudah tidak bekerja sama. Batasi juga jumlah percobaan login.

Jangan lupakan akses di luar CMS, seperti panel hosting, FTP, dan akun pendaftaran domain. Penyerang yang menguasai akun domain bisa mengalihkan seluruh website dan email perusahaan.

Pencadangan 3-2-1 dan Uji Pemulihan

Cadangan data adalah jaring pengaman terakhir ketika semua lapisan lain gagal, termasuk saat sistem terkena ransomware. Terapkan aturan 3-2-1: simpan tiga salinan data di dua jenis media berbeda, dengan satu salinan di luar lokasi server, misalnya di penyimpanan cloud terpisah.

Cadangan harus mencakup berkas website dan basis data. Jika memakai basis data MySQL, Anda bisa langsung menerapkan panduan pencadangan basis data MySQL otomatis. Langkah yang sering terlupa adalah uji pemulihan. Cobalah memulihkan cadangan ke server uji secara berkala karena cadangan yang tidak pernah Anda uji belum tentu berfungsi saat Anda membutuhkannya.

Tentukan pula berapa lama Anda menyimpan cadangan, misalnya cadangan harian untuk seminggu terakhir dan cadangan mingguan untuk sebulan terakhir. Peretasan sering baru terdeteksi beberapa minggu kemudian. Oleh karena itu, Anda memerlukan salinan dari masa sebelum website tercemar.

Tambah Lapisan Perlindungan dan Validasi Input

Web Application Firewall (WAF) menyaring lalu lintas berbahaya seperti percobaan injeksi atau serbuan login otomatis sebelum sampai ke server. Banyak layanan CDN menyediakan WAF dan perlindungan DDoS sekaligus mempercepat website. Namun, WAF hanya lapisan tambahan, bukan pengganti kode yang aman.

Di sisi kode, jadikan OWASP Top 10 sebagai acuan. Edisi terbarunya, OWASP Top 10:2025, tetap menempatkan Broken Access Control di urutan pertama, menaikkan Security Misconfiguration ke urutan kedua, dan memperluas kategori komponen usang menjadi Software Supply Chain Failures. Artinya, OWASP kini memandang kesalahan pengaturan hak akses dan konfigurasi sebagai risiko utama keamanan aplikasi web.

Praktik dasarnya sederhana: validasi semua input di sisi server, gunakan query berparameter untuk mencegah injeksi SQL, lakukan escape pada setiap keluaran untuk mencegah XSS, dan periksa hak akses pengguna pada setiap aksi, bukan hanya dengan menyembunyikan tombol di tampilan.

Pantau Log dan Tanda-Tanda Peretasan

Peretasan yang tidak terdeteksi bisa berlangsung lama. Aktifkan pemantauan uptime agar Anda tahu saat pengunjung tidak bisa membuka website. Daftarkan juga website ke Google Search Console untuk menerima peringatan masalah keamanan. Simpan log akses dan log aplikasi di tempat yang aman agar penyerang tidak bisa menghapusnya.

Biasakan memeriksa riwayat login admin, perubahan berkas yang tidak Anda kenali, dan akun admin baru yang muncul tiba-tiba. Sesekali ketik site:namadomainanda.com di Google untuk melihat apakah ada halaman asing yang ikut terindeks atas nama website Anda, misalnya halaman judi daring. Siapkan juga rencana sederhana bila terjadi insiden: siapa yang perlu Anda hubungi, bagaimana mengisolasi website, dan cadangan mana yang menjadi sumber pemulihan.

Mulai dari Daftar Periksa Ini

Keamanan website bukan proyek sekali jadi, melainkan kebiasaan. Jika semuanya terasa banyak, mulailah dari lima langkah berikut minggu ini.

  1. Perbarui CMS, plugin, tema, dan paket, lalu hapus yang tidak terpakai.

  2. Pastikan HTTPS aktif dan mode debug di server produksi mati.

  3. Aktifkan 2FA untuk semua akun admin dan rapikan hak aksesnya.

  4. Jadwalkan pencadangan otomatis dengan aturan 3-2-1 dan uji pemulihannya.

  5. Pasang pemantauan uptime dan daftarkan website ke Google Search Console.
