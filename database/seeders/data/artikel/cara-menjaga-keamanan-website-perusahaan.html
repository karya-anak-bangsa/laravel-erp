Banyak pemilik usaha baru sadar website-nya diretas ketika pelanggan bertanya mengapa hasil pencarian Google menampilkan halaman judi online atas nama perusahaan mereka. Pada titik itu kerusakan sudah terjadi: reputasi tercoreng, peringkat pencarian anjlok, dan pemulihannya memakan waktu serta biaya.

Kabar baiknya, sebagian besar serangan bisa dicegah dengan kebiasaan dasar yang dijalankan secara konsisten. Panduan ini ditujukan bagi pemilik bisnis dan tim IT kecil, mulai dari update rutin, HTTPS, pengamanan akun admin, backup, perlindungan tambahan, hingga pemantauan.

Rutin Update CMS, Plugin, dan Framework

Banyak peretasan memanfaatkan celah yang sebenarnya sudah ditambal pengembangnya, hanya saja pemilik website belum memasang update. Website WordPress dengan plugin dan tema yang jarang diperbarui adalah contoh yang paling umum. Hal yang sama berlaku untuk aplikasi buatan sendiri yang memakai framework seperti Laravel, beserta paket Composer dan npm di dalamnya.

Jadwalkan pemeriksaan update setidaknya sekali seminggu, uji dulu di salinan website (staging) bila memungkinkan, lalu hapus plugin dan tema yang tidak dipakai. Hindari juga tema atau plugin berbayar versi bajakan (nulled), karena sering sudah disisipi kode jahat sejak awal.

Bagi developer, jalankan composer audit dan npm audit secara rutin. Kedua perintah ini memeriksa apakah paket yang dipakai proyek punya kerentanan yang sudah diketahui, sehingga Anda tahu paket mana yang perlu segera diperbarui.

Pasang HTTPS dan Rapikan Konfigurasi Server

HTTPS mengenkripsi data antara pengunjung dan server, termasuk isian formulir dan login admin. Sertifikat SSL/TLS kini bisa didapat gratis dari Let's Encrypt, dan banyak penyedia hosting sudah menyediakannya dalam beberapa klik. Pastikan semua alamat HTTP dialihkan ke HTTPS.

Setelah itu, rapikan konfigurasi. Matikan mode debug di server produksi, misalnya APP_DEBUG=false pada Laravel, agar pesan error tidak membocorkan detail sistem. Tambahkan header keamanan seperti HSTS dan Content-Security-Policy, dan pastikan berkas cadangan atau berkas .env tidak bisa diunduh publik.

Kunci Pintu Admin: Password, 2FA, dan Hak Akses Minimum

Halaman login admin adalah pintu yang paling sering dicoba penyerang, biasanya dengan menebak password secara otomatis. Perkuat pintu ini dengan kebiasaan berikut.

  • Gunakan password panjang dan unik untuk setiap akun admin, simpan di pengelola password, dan jangan memakai satu akun bersama-sama.

  • Aktifkan autentikasi dua faktor (2FA) untuk admin website, panel hosting, dan email domain.

  • Terapkan prinsip hak akses minimum: penulis konten cukup diberi akses editor, bukan administrator.

  • Hapus akun karyawan atau vendor yang sudah tidak bekerja sama, dan batasi jumlah percobaan login.

Jangan lupakan akses di luar CMS, seperti panel hosting, FTP, dan akun pendaftaran domain. Penyerang yang menguasai akun domain bisa mengalihkan seluruh website dan email perusahaan.

Backup 3-2-1 dan Uji Pemulihan

Backup adalah jaring pengaman terakhir ketika semua lapisan lain gagal, termasuk saat terkena ransomware. Pegang aturan 3-2-1: simpan tiga salinan data, di dua jenis media berbeda, dan satu salinan berada di luar lokasi server, misalnya di penyimpanan cloud terpisah.

Backup harus mencakup berkas website dan database. Untuk database MySQL, panduan backup database MySQL otomatis bisa langsung diterapkan. Yang sering terlupa adalah uji pemulihan. Cobalah memulihkan backup ke server uji secara berkala, karena backup yang tidak pernah diuji belum tentu bisa dipakai saat dibutuhkan.

Tentukan pula berapa lama backup disimpan, misalnya harian untuk seminggu terakhir dan mingguan untuk sebulan terakhir. Peretasan sering baru ketahuan beberapa minggu kemudian, jadi Anda perlu salinan yang dibuat sebelum website tercemar.

Tambah Lapisan Perlindungan dan Validasi Input

Web Application Firewall (WAF) menyaring lalu lintas berbahaya sebelum sampai ke server, seperti percobaan injeksi atau serbuan login otomatis. Banyak layanan CDN menyediakan WAF dan perlindungan DDoS sekaligus mempercepat website. Namun, WAF hanya lapisan tambahan, bukan pengganti kode yang aman.

Di sisi kode, jadikan OWASP Top 10 sebagai acuan. Edisi terbarunya, OWASP Top 10:2025, tetap menempatkan Broken Access Control di urutan pertama, menaikkan Security Misconfiguration ke urutan kedua, dan memperluas kategori komponen usang menjadi Software Supply Chain Failures. Artinya, kesalahan pengaturan hak akses dan konfigurasi kini dipandang sebagai risiko keamanan aplikasi web yang paling utama.

Praktik dasarnya sederhana: validasi semua input di sisi server, gunakan query berparameter untuk mencegah SQL injection, escape setiap output untuk mencegah XSS, dan periksa hak akses pengguna pada setiap aksi, bukan hanya dengan menyembunyikan tombol di tampilan.

Pantau Log dan Tanda-tanda Peretasan

Peretasan yang tidak terdeteksi bisa berlangsung lama. Aktifkan pemantauan uptime agar Anda tahu saat website tidak bisa diakses, daftarkan website ke Google Search Console untuk menerima peringatan masalah keamanan, dan simpan log akses serta log aplikasi di tempat yang tidak bisa dihapus penyerang.

Biasakan memeriksa riwayat login admin, perubahan berkas yang tidak dikenal, dan akun admin baru yang muncul tiba-tiba. Sesekali ketik site:namadomainanda.com di Google untuk melihat apakah ada halaman asing, misalnya halaman judi online, yang ikut terindeks atas nama website Anda. Siapkan juga rencana sederhana bila terjadi insiden: siapa yang dihubungi, bagaimana mengisolasi website, dan dari backup mana pemulihan dilakukan.

Mulai dari Daftar Periksa Ini

Keamanan website bukan proyek sekali jadi, melainkan kebiasaan. Jika semuanya terasa banyak, mulailah dari lima langkah berikut minggu ini.

  1. Perbarui CMS, plugin, tema, dan dependensi, lalu hapus yang tidak terpakai.

  2. Pastikan HTTPS aktif dan mode debug di server produksi mati.

  3. Aktifkan 2FA untuk semua akun admin dan rapikan hak aksesnya.

  4. Jadwalkan backup otomatis dengan aturan 3-2-1 dan uji pemulihannya.

  5. Pasang pemantauan uptime dan daftarkan website ke Google Search Console.
