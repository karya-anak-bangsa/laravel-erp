Anda menyalin potongan kode dari tutorial lama, menjalankannya, lalu angka yang muncul di konsol ternyata tidak sesuai harapan. Setelah ditelusuri, penyebabnya sering kali sepele: sebuah variabel dideklarasikan dengan var di tempat yang seharusnya memakai let. Ketiga kata kunci ini memang tampak serupa, tetapi aturan mainnya cukup berbeda.

Sebelum ECMAScript 2015 (ES6), var adalah satu-satunya cara membuat variabel di JavaScript. Kata kunci let dan const baru hadir di standar itu untuk menambal kelemahannya. Artikel ini membahas perbedaan ketiganya dari sisi cakupan, hoisting, deklarasi ulang, dan perilaku const pada objek, lengkap dengan bug klasik yang masih sering ditemui serta kebiasaan yang sebaiknya Anda pakai.

Cakupan: Fungsi versus Blok

Perbedaan paling mendasar ada pada cakupan atau scope, yaitu bagian kode tempat sebuah variabel bisa diakses. Variabel var berlaku di seluruh fungsi tempat ia dideklarasikan. Sementara itu, let dan const hanya berlaku di dalam blok kurung kurawal terdekat, misalnya blok if, for, atau while.

Ambil contoh if (true) { var pesan = "halo"; } console.log(pesan);. Kode ini mencetak halo, karena var tidak mengenal batas blok if. Bila var di situ diganti let, baris console.log justru berhenti dengan ReferenceError: pesan is not defined. Perilaku kedua inilah yang lebih masuk akal: variabel untuk urusan di dalam blok tidak ikut bocor ke luar.

Ada satu efek samping lain. Di tingkat paling atas sebuah skrip biasa (bukan modul), var juga menempel sebagai properti objek global. Di browser, var versi = "1.0"; bisa dibaca lewat window.versi, sedangkan variabel let dan const tidak. Pada halaman yang memuat banyak skrip, var global seperti ini rawan bertabrakan dengan variabel milik skrip lain.

Hoisting dan Temporal Dead Zone

Sebelum menjalankan baris pertama sebuah cakupan, JavaScript lebih dulu mendaftarkan semua deklarasi di dalamnya. Gejala ini dikenal sebagai hoisting, seakan-akan deklarasi diangkat ke atas. Bedanya, var langsung diberi nilai awal undefined, sedangkan let dan const dibiarkan dalam keadaan belum siap dipakai.

Akibatnya, console.log(nama); var nama = "Budi"; tidak error dan hanya mencetak undefined. Kedengarannya ramah, padahal berbahaya: program terus berjalan dengan nilai yang salah, dan bug baru ketahuan jauh di belakang. Dengan let, kode yang sama langsung berhenti dengan pesan Cannot access 'nama' before initialization.

Rentang dari awal blok sampai baris deklarasi disebut temporal dead zone (TDZ). Selama berada di zona ini, variabel let dan const sama sekali tidak bisa disentuh, bahkan oleh typeof yang biasanya aman dipakai pada variabel yang belum dideklarasikan. Pesan error yang tegas seperti ini jauh lebih mudah dilacak ketimbang undefined yang diam-diam merambat ke mana-mana.

Kata "temporal" di sini penting, karena zona ini soal waktu, bukan posisi baris. Sebuah fungsi boleh membaca const yang dideklarasikan di bawahnya, asalkan fungsi itu baru dipanggil setelah baris deklarasi tersebut dijalankan.

Deklarasi Ulang dan Pengisian Ulang

Dua istilah ini sering tertukar. Deklarasi ulang berarti menulis var, let, atau const lagi untuk nama yang sama, sedangkan pengisian ulang berarti memberi nilai baru dengan tanda sama dengan. Aturan ketiganya berbeda:

  • Variabel var boleh dideklarasikan ulang sekaligus diisi ulang. var stok = 10; var stok = 20; berjalan mulus, dan justru di situ masalahnya: Anda bisa tanpa sadar memakai ulang nama yang sudah dipakai di bagian lain fungsi.

  • Variabel let tidak boleh dideklarasikan ulang di cakupan yang sama, tetapi boleh diisi ulang, misalnya stok = stok - 1;. Deklarasi ganda langsung ditolak dengan SyntaxError: Identifier 'stok' has already been declared.

  • Konstanta const tidak boleh keduanya. Nilainya wajib diberikan saat deklarasi, dan setelah const BATAS_LOGIN = 5;, perintah BATAS_LOGIN = 10 memicu TypeError: Assignment to constant variable.

SyntaxError pada deklarasi ganda muncul saat kode diurai, sebelum satu baris pun dijalankan. Artinya kesalahan ketahuan sejak awal, bukan ketika pengguna sudah telanjur menekan tombol.

Isi Objek const Tetap Bisa Diubah

Banyak pemula mengira const membuat nilainya beku. Yang sebenarnya dikunci adalah ikatan antara nama variabel dan nilainya, bukan isi nilai itu sendiri. Untuk angka dan teks hasilnya sama saja, karena kedua jenis nilai itu memang tidak bisa diubah dari dalam.

Lain cerita dengan objek dan array. Setelah const keranjang = [];, perintah keranjang.push("buku"); tetap sah, begitu pula mengganti properti objek seperti pengguna.nama = "Rina". Yang dilarang hanyalah mengarahkan nama itu ke array atau objek lain, misalnya keranjang = [].

Bila Anda benar-benar butuh objek yang tidak bisa diubah, gunakan Object.freeze, misalnya const WARNA_STATUS = Object.freeze({ aktif: "hijau", nonaktif: "abu-abu" });. Ingat, pembekuan ini dangkal: objek di dalam objek tetap bisa diubah kecuali ikut dibekukan. Di luar strict mode, upaya mengganti properti objek beku bahkan diabaikan begitu saja tanpa pesan error.

Bug Klasik var di Dalam Perulangan

Contoh paling terkenal muncul saat perulangan dipadukan dengan kode yang baru berjalan belakangan, seperti setTimeout atau event listener. Jalankan for (var i = 1; i <= 3; i++) { setTimeout(() => console.log(i), 100); } di konsol browser. Alih-alih 1, 2, 3, yang tercetak justru 4, 4, 4.

Penyebabnya, hanya ada satu variabel i untuk seluruh perulangan. Saat ketiga fungsi di dalam setTimeout akhirnya dijalankan, perulangan sudah lama selesai dan i sudah bernilai 4. Dalam aplikasi nyata, gejalanya berupa deretan tombol yang semuanya menampilkan angka yang sama saat diklik.

Cukup ganti var dengan let, dan hasilnya menjadi 1, 2, 3. Pada perulangan for, let membuat ikatan baru di setiap putaran, sehingga setiap fungsi menyimpan nilai i miliknya sendiri. Dulu masalah ini diakali dengan fungsi pembungkus yang langsung dipanggil (IIFE); sekarang cukup satu kata kunci.

Satu catatan: const tidak bisa menjadi penghitung di for klasik, karena i++ mencoba mengubah nilainya. Namun const cocok untuk for...of, misalnya for (const buah of ["apel", "jeruk"]) { console.log(buah); }, sebab setiap putaran mendapat variabel baru.

Jadi, Kapan Memakai Masing-masing?

Aturan praktis yang dipakai banyak tim JavaScript saat ini cukup sederhana:

  • Jadikan const pilihan pertama untuk semua variabel, termasuk objek dan array yang isinya akan ditambah atau diubah.

  • Pakai let hanya bila nilainya memang perlu diganti, misalnya penghitung, total yang dijumlahkan bertahap, atau status yang berubah di dalam perulangan.

  • Hindari var di kode baru. Cukup kenali perilakunya agar Anda bisa membaca kode lama dan pustaka warisan dengan benar.

  • Aktifkan aturan ESLint no-var dan prefer-const agar kebiasaan ini dijaga otomatis. Sebagian temuan prefer-const bahkan bisa diperbaiki sendiri lewat opsi --fix.

Dengan const sebagai bawaan, setiap let yang muncul menjadi sinyal bagi pembaca kode bahwa nilai variabel itu akan berubah dan perlu diperhatikan. Saat merapikan kode lama, jangan mengganti semua var secara massal tanpa pengujian, karena bisa saja ada bagian yang sengaja memakai variabel di luar bloknya. Untuk rincian lebih lanjut, halaman let di MDN Web Docs layak disimpan sebagai rujukan.
