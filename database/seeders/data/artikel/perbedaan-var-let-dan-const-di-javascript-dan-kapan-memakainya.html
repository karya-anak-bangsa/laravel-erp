Anda menyalin potongan kode dari tutorial lama dan menjalankannya, tetapi angka yang muncul di konsol ternyata tidak sesuai harapan. Setelah Anda menelusurinya, penyebabnya sering kali sepele: kode itu mendeklarasikan sebuah variabel dengan var di tempat yang seharusnya memakai let. Kata kunci var, let, dan const memang tampak serupa, tetapi aturan mainnya cukup berbeda.

Sebelum ECMAScript 2015 (ES6), var adalah satu-satunya cara membuat variabel di JavaScript. Standar itulah yang menghadirkan let dan const untuk menambal kelemahan var. Artikel ini membahas perbedaan ketiganya dari sisi cakupan, hoisting, deklarasi ulang, dan perilaku const pada objek. Pembahasannya juga mencakup bug klasik yang masih sering muncul serta kebiasaan yang sebaiknya Anda pakai.

Cakupan: Fungsi versus Blok

Perbedaan paling mendasar ada pada cakupan atau scope, yaitu bagian kode yang dapat mengakses sebuah variabel. Variabel var berlaku di seluruh fungsi tempat Anda mendeklarasikannya. Sementara itu, variabel let dan const hanya berlaku di dalam blok kurung kurawal terdekat, misalnya blok if, for, atau while.

Ambil contoh if (true) { var pesan = "halo"; } console.log(pesan);. Kode ini mencetak halo karena var tidak mengenal batas blok if. Bila Anda mengganti var tersebut dengan let, baris console.log justru berhenti dengan ReferenceError: pesan is not defined. Perilaku kedua inilah yang lebih masuk akal: variabel untuk urusan di dalam blok tidak ikut bocor ke luar.

Ada satu efek samping lain. Di tingkat paling atas sebuah skrip biasa (bukan modul), var juga menempel sebagai properti objek global. Di peramban, deklarasi var versi = "1.0"; menghasilkan properti window.versi, sedangkan deklarasi let dan const tidak. Pada halaman yang memuat banyak skrip, var global seperti ini rawan bertabrakan dengan variabel milik skrip lain.

Hoisting dan Temporal Dead Zone

Sebelum menjalankan baris pertama sebuah cakupan, JavaScript terlebih dahulu mendaftarkan semua deklarasi di dalamnya. Pengembang menyebut gejala ini hoisting karena deklarasi seakan-akan terangkat ke atas. Bedanya, JavaScript langsung memberi variabel var nilai awal undefined, sedangkan variabel let dan const tetap dalam keadaan belum siap pakai.

Akibatnya, kode console.log(nama); var nama = "Budi"; tidak memicu galat dan hanya mencetak undefined. Perilaku ini terdengar ramah, padahal berbahaya: program terus berjalan dengan nilai yang salah dan bug baru terdeteksi lama kemudian. Dengan let, kode yang sama langsung berhenti dengan pesan Cannot access 'nama' before initialization.

Rentang dari awal blok sampai baris deklarasi bernama temporal dead zone (TDZ). Selama variabel let dan const berada di zona ini, kode apa pun sama sekali tidak bisa menyentuhnya, termasuk typeof yang biasanya aman untuk memeriksa variabel tanpa deklarasi. Pesan galat yang tegas seperti ini jauh lebih memudahkan pelacakan daripada undefined yang diam-diam merambat ke mana-mana.

Kata temporal di sini penting karena zona ini menyangkut waktu, bukan posisi baris. Sebuah fungsi boleh membaca const yang deklarasinya berada di bawah fungsi itu. Syaratnya, kode Anda baru memanggil fungsi tersebut setelah JavaScript menjalankan baris deklarasi const.

Deklarasi Ulang dan Pengisian Ulang

Dua istilah ini sering tertukar. Deklarasi ulang berarti menulis var, let, atau const lagi untuk nama yang sama, sedangkan pengisian ulang berarti memberi nilai baru dengan tanda sama dengan. Aturan ketiganya berbeda:

  • Variabel var mengizinkan deklarasi ulang sekaligus pengisian ulang. Kode var stok = 10; var stok = 20; berjalan mulus. Justru di situlah masalahnya: Anda bisa tanpa sadar memakai ulang nama yang sudah terpakai di bagian lain fungsi.

  • Variabel let menolak deklarasi ulang di cakupan yang sama, tetapi mengizinkan pengisian ulang, misalnya stok = stok - 1;. Deklarasi ganda langsung memicu SyntaxError: Identifier 'stok' has already been declared.

  • Konstanta const menolak keduanya. Anda wajib memberikan nilainya saat deklarasi. Setelah const BATAS_LOGIN = 5;, perintah BATAS_LOGIN = 10 memicu TypeError: Assignment to constant variable.

SyntaxError pada deklarasi ganda muncul saat JavaScript mengurai kode sebelum menjalankan satu baris pun. Artinya, kesalahan terdeteksi sejak awal, bukan ketika pengguna sudah telanjur menekan tombol.

Isi Objek const Tetap Bisa Berubah

Banyak pemula mengira const membuat nilainya beku. Sebenarnya, const hanya mengunci ikatan antara nama variabel dan nilainya, bukan isi nilai itu sendiri. Perbedaan ini tidak berpengaruh pada angka dan teks karena kedua jenis nilai itu memang tidak bisa berubah dari dalam.

Objek dan array berperilaku lain. Setelah const keranjang = [];, perintah keranjang.push("buku"); tetap sah. Mengganti properti objek, seperti pengguna.nama = "Rina", juga sah. Kata kunci const hanya melarang Anda mengarahkan nama itu ke array atau objek lain, misalnya keranjang = [].

Bila Anda benar-benar membutuhkan objek yang tidak bisa berubah, gunakan Object.freeze, misalnya const WARNA_STATUS = Object.freeze({ aktif: "hijau", nonaktif: "abu-abu" });. Ingat, pembekuan ini dangkal: objek di dalam objek tetap bisa berubah kecuali Anda ikut membekukannya. Di luar strict mode, JavaScript bahkan mengabaikan upaya mengganti properti objek beku begitu saja tanpa pesan galat.

Bug Klasik var di dalam Perulangan

Contoh paling terkenal muncul saat Anda memadukan perulangan dengan kode yang baru berjalan belakangan, seperti setTimeout atau event listener. Jalankan for (var i = 1; i <= 3; i++) { setTimeout(() => console.log(i), 100); } di konsol peramban. Alih-alih mencetak 1, 2, 3, kode itu justru mencetak 4, 4, 4.

Penyebabnya, hanya ada satu variabel i untuk seluruh perulangan. Saat ketiga fungsi di dalam setTimeout akhirnya berjalan, perulangan sudah lama selesai dan i sudah bernilai 4. Dalam aplikasi nyata, gejalanya berupa deretan tombol yang semuanya menampilkan angka yang sama saat pengguna mengekliknya.

Cukup ganti var dengan let. Hasilnya langsung menjadi 1, 2, 3. Pada perulangan for, let membuat ikatan baru di setiap putaran sehingga setiap fungsi menyimpan nilai i miliknya sendiri. Dahulu, pengembang mengakali masalah ini dengan fungsi pembungkus yang langsung berjalan (IIFE). Sekarang, satu kata kunci sudah cukup.

Satu catatan: const tidak bisa menjadi penghitung di for klasik karena i++ mencoba mengubah nilainya. Namun, const cocok untuk for...of, misalnya for (const buah of ["apel", "jeruk"]) { console.log(buah); }. Setiap putaran perulangan ini mendapat variabel baru.

Kapan Memakai Masing-Masing?

Banyak tim JavaScript saat ini memakai aturan praktis yang cukup sederhana:

  • Jadikan const pilihan pertama untuk semua variabel, termasuk objek dan array yang isinya akan bertambah atau berubah.

  • Pakai let hanya bila Anda memang perlu mengganti nilainya, misalnya untuk penghitung, total yang bertambah secara bertahap, atau status yang berubah di dalam perulangan.

  • Hindari var di kode baru. Cukup kenali perilakunya agar Anda bisa membaca kode lama dan pustaka warisan dengan benar.

  • Aktifkan aturan ESLint no-var dan prefer-const agar kebiasaan ini terjaga secara otomatis. Opsi --fix bahkan bisa memperbaiki sendiri sebagian temuan prefer-const.

Dengan const sebagai bawaan, setiap let yang muncul menjadi sinyal bagi pembaca kode bahwa nilai variabel itu akan berubah dan perlu mendapat perhatian. Saat merapikan kode lama, jangan mengganti semua var secara massal tanpa pengujian karena bisa saja ada bagian yang sengaja memakai variabel di luar bloknya. Simpan halaman let di MDN Web Docs sebagai rujukan untuk rincian lebih lanjut.
