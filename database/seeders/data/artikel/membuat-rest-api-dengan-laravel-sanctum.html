Aplikasi kasir di ponsel, dashboard berbasis React, atau integrasi dengan sistem mitra punya kebutuhan yang sama: mengambil dan mengirim data lewat API yang aman. Untuk keperluan ini Laravel menyediakan Sanctum, paket autentikasi resmi yang ringan dan tidak serumit OAuth.

Di artikel ini kita membangun REST API sederhana untuk data artikel: memasang Sanctum, menerbitkan token saat login, melindungi endpoint, membatasi hak token, membentuk respons JSON yang rapi, membatasi jumlah permintaan, lalu mengujinya dengan curl atau Postman.

Memasang Sanctum dengan install:api

Proyek Laravel 13 tidak menyertakan berkas routes/api.php secara bawaan. Jalankan php artisan install:api; perintah ini memasang paket Sanctum, membuat routes/api.php, dan menerbitkan migration untuk tabel personal_access_tokens. Jawab yes saat ditanya apakah migration ingin langsung dijalankan.

Semua route di routes/api.php otomatis berawalan /api dan memakai middleware group api yang stateless, tanpa session dan tanpa token CSRF. Langkah terakhir, tambahkan trait HasApiTokens dari namespace Laravel\Sanctum ke model User, sehingga baris trait-nya menjadi use HasApiTokens, HasFactory, Notifiable;.

Kapan sebaiknya memakai Laravel Passport? Bila aplikasi Anda harus menjadi server OAuth2 penuh, misalnya mengizinkan aplikasi pihak ketiga meminta akses atas nama pengguna. Untuk aplikasi milik sendiri seperti aplikasi mobile atau frontend terpisah, Sanctum biasanya sudah lebih dari cukup.

Endpoint Login yang Menerbitkan Token

Klien API tidak memakai cookie session, melainkan token yang dikirim di setiap permintaan. Buat route POST /api/login yang menerima email, password, dan device_name, lalu ikuti alur berikut:

  1. Validasi ketiga field, sebaiknya dengan Form Request seperti dibahas di artikel validasi form dengan Form Request.

  2. Cari user berdasarkan email, lalu cocokkan password dengan Hash::check($request->password, $user->password).

  3. Jika user tidak ditemukan atau password salah, lempar ValidationException agar klien menerima status 422 dengan pesan yang jelas.

  4. Jika cocok, terbitkan token dengan $user->createToken($request->device_name)->plainTextToken dan kembalikan nilainya dalam respons JSON.

Token hanya bisa dilihat sekali. Sanctum menyimpannya di database dalam bentuk hash SHA-256, jadi klien wajib menyimpan nilai plainTextToken saat itu juga. Untuk logout, hapus token yang sedang dipakai dengan $request->user()->currentAccessToken()->delete();.

Melindungi Endpoint dan Membatasi Hak Token

Buat controller khusus API dengan php artisan make:controller Api/PostController --api --model=Post. Opsi --api menghilangkan method create dan edit yang hanya relevan untuk formulir HTML.

Daftarkan route-nya di routes/api.php sekaligus dengan perlindungan auth:sanctum, setelah mengimpor kelas App\Http\Controllers\Api\PostController: Route::apiResource('posts', PostController::class)->middleware('auth:sanctum');. Satu baris ini menghasilkan lima endpoint, yaitu index, store, show, update, dan destroy, yang semuanya menolak permintaan tanpa token valid dengan status 401.

Ikuti konvensi REST agar API mudah dipahami pengembang lain: GET /api/posts untuk daftar, POST /api/posts untuk membuat, GET /api/posts/{post} untuk detail, PUT atau PATCH untuk mengubah, dan DELETE untuk menghapus. Gunakan juga kode status yang tepat. Resource untuk model yang baru dibuat otomatis dibalas dengan status 201, sedangkan aksi hapus cukup mengembalikan response()->noContent() yang berstatus 204.

Token juga bisa diberi hak terbatas lewat abilities, mirip scope di OAuth. Token untuk aplikasi pembaca, misalnya, cukup diberi hak baca: $user->createToken('aplikasi-pembaca', ['posts:read']). Di controller, periksa haknya dengan $request->user()->tokenCan('posts:write') sebelum menyimpan atau menghapus data.

Bila lebih suka memeriksanya di level route, daftarkan alias middleware abilities dan ability di bootstrap/app.php, masing-masing mengarah ke kelas CheckAbilities dan CheckForAnyAbility milik Sanctum. Setelah itu route bisa dijaga dengan middleware seperti abilities:posts:write.

Respons Rapi dengan API Resource

Mengembalikan model mentah sebagai JSON memang praktis, tetapi semua kolom ikut terkirim dan format respons berubah setiap kali struktur tabel berubah. API Resource menjadi lapisan penerjemah di antaranya. Buat dengan php artisan make:resource PostResource, lalu tentukan field yang dikirim di method toArray().

Di controller, kembalikan daftar artikel dengan return PostResource::collection(Post::with('user')->paginate(15));. Laravel membungkus data dalam kunci data dan menambahkan links serta meta berisi informasi halaman. Perhatikan with('user'): tanpa eager loading, resource yang menampilkan nama penulis akan memicu masalah yang dibahas di artikel Eloquent relationship dan N+1 query.

Di dalam resource, gunakan $this->whenLoaded('user') agar relasi hanya ditampilkan bila memang sudah dimuat. Laravel 13 juga menyediakan resource yang mengikuti spesifikasi JSON:API lewat php artisan make:resource PostResource --json-api, berguna bila klien Anda mengharapkan format tersebut.

Membatasi Jumlah Permintaan

Middleware group api tidak memasang pembatas laju secara bawaan, padahal endpoint seperti login rawan ditebak password-nya berulang kali. Definisikan limiter di method boot milik AppServiceProvider: RateLimiter::for('api', fn (Request $request) => Limit::perMinute(60)->by($request->user()?->id ?: $request->ip()));

Pasang limiter itu dengan middleware throttle:api pada route atau grup route. Untuk endpoint login, buat limiter terpisah yang jauh lebih ketat, misalnya lima percobaan per menit. Klien yang melewati batas akan menerima status 429 Too Many Requests.

Menguji dengan curl atau Postman

Jalankan server lokal dengan php artisan serve, lalu minta token lewat terminal:

curl -X POST http://127.0.0.1:8000/api/login -H "Accept: application/json" -d "email=budi@example.com" -d "password=rahasia123" -d "device_name=laptop"

Salin token dari respons, lalu panggil endpoint yang dilindungi:

curl http://127.0.0.1:8000/api/posts -H "Accept: application/json" -H "Authorization: Bearer TOKEN_ANDA"

Header Accept: application/json penting. Tanpa header itu, permintaan yang gagal autentikasi bisa diarahkan ke halaman login alih-alih dibalas status 401 berformat JSON.

Di Windows PowerShell 5.1, ketik curl.exe karena curl di sana adalah alias untuk Invoke-WebRequest. Jika lebih suka antarmuka grafis, Postman bisa melakukan hal yang sama: pilih tipe Bearer Token di tab Authorization, lalu tambahkan header Accept.

Langkah Berikutnya

Secara bawaan token Sanctum tidak pernah kedaluwarsa. Untuk aplikasi produksi, atur masa berlaku lewat opsi expiration di config/sanctum.php, lalu jadwalkan php artisan sanctum:prune-expired --hours=24 untuk membersihkan token yang sudah lama kedaluwarsa.

Setelah itu, lengkapi API dengan pengujian otomatis memakai Sanctum::actingAs(), dokumentasikan setiap endpoint, dan pastikan seluruh lalu lintas berjalan lewat HTTPS. Rujukan lengkapnya ada di dokumentasi Laravel Sanctum.
