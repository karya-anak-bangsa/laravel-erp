Aplikasi kasir di ponsel, dasbor berbasis React, atau integrasi dengan sistem mitra memiliki kebutuhan yang sama: mengambil dan mengirim data lewat API yang aman. Laravel menyediakan Sanctum untuk keperluan ini. Sanctum adalah paket autentikasi resmi yang ringan dan tidak serumit OAuth.

Di artikel ini, kita akan membangun REST API sederhana untuk data artikel: memasang Sanctum, menerbitkan token saat pengguna masuk, melindungi endpoint, membatasi hak token, membentuk respons JSON yang rapi, membatasi jumlah permintaan, lalu mengujinya dengan curl atau Postman.

Memasang Sanctum dengan install:api

Proyek Laravel 13 tidak menyertakan berkas routes/api.php secara bawaan. Jalankan php artisan install:api. Perintah ini memasang paket Sanctum, membuat routes/api.php, dan menerbitkan migrasi untuk tabel personal_access_tokens. Jawab yes saat perintah itu bertanya apakah Anda ingin langsung menjalankan migrasinya.

Semua rute di routes/api.php otomatis berawalan /api dan memakai grup middleware api yang stateless, yaitu tanpa sesi dan tanpa token CSRF. Langkah terakhir, tambahkan trait HasApiTokens dari namespace Laravel\Sanctum ke model User. Baris trait-nya pun menjadi use HasApiTokens, HasFactory, Notifiable;.

Kapan sebaiknya Anda memakai Laravel Passport? Passport cocok bila aplikasi Anda harus menjadi server OAuth2 penuh, misalnya untuk mengizinkan aplikasi pihak ketiga meminta akses atas nama pengguna. Sanctum biasanya sudah lebih dari cukup untuk aplikasi milik sendiri, seperti aplikasi ponsel atau frontend terpisah.

Endpoint Login yang Menerbitkan Token

Klien API tidak memakai cookie sesi, melainkan token yang menyertai setiap permintaan. Buat rute POST /api/login yang menerima field email, password, dan device_name, lalu ikuti alur berikut:

  1. Validasi ketiga field itu, sebaiknya dengan Form Request seperti yang kita bahas di artikel validasi form dengan Form Request.

  2. Cari pengguna berdasarkan email, lalu cocokkan password-nya dengan Hash::check($request->password, $user->password).

  3. Jika pengguna tidak ada atau password-nya salah, lempar ValidationException agar klien menerima status 422 dengan pesan yang jelas.

  4. Jika cocok, terbitkan token dengan $user->createToken($request->device_name)->plainTextToken dan kembalikan nilainya dalam respons JSON.

Nilai token hanya tampil sekali. Sanctum menyimpannya di basis data dalam bentuk hash SHA-256. Oleh karena itu, klien wajib menyimpan nilai plainTextToken saat itu juga. Saat pengguna keluar, hapus token yang sedang aktif dengan $request->user()->currentAccessToken()->delete();.

Melindungi Endpoint dan Membatasi Hak Token

Buat controller khusus API dengan php artisan make:controller Api/PostController --api --model=Post. Opsi --api menghilangkan method create dan edit yang hanya relevan untuk formulir HTML.

Impor kelas App\Http\Controllers\Api\PostController, lalu daftarkan rutenya di routes/api.php sekaligus dengan perlindungan auth:sanctum: Route::apiResource('posts', PostController::class)->middleware('auth:sanctum');. Satu baris ini menghasilkan lima endpoint, yaitu index, store, show, update, dan destroy. Kelima endpoint itu menolak permintaan tanpa token valid dengan status 401.

Ikuti konvensi REST agar pengembang lain mudah memahami API Anda: GET /api/posts untuk daftar, POST /api/posts untuk membuat, GET /api/posts/{post} untuk detail, PUT atau PATCH untuk mengubah, dan DELETE untuk menghapus. Gunakan juga kode status yang tepat. Laravel otomatis mengirim resource untuk model baru dengan status 201, sedangkan aksi hapus cukup mengembalikan response()->noContent() yang berstatus 204.

Anda juga bisa memberi token hak terbatas lewat abilities, mirip scope di OAuth. Token untuk aplikasi pembaca, misalnya, cukup mendapat hak baca: $user->createToken('aplikasi-pembaca', ['posts:read']). Di controller, periksa haknya dengan $request->user()->tokenCan('posts:write') sebelum menyimpan atau menghapus data.

Bila Anda lebih suka memeriksanya di tingkat rute, daftarkan alias middleware abilities dan ability di bootstrap/app.php. Masing-masing alias mengarah ke kelas CheckAbilities dan CheckForAnyAbility milik Sanctum. Setelah itu, Anda bisa menjaga rute dengan middleware seperti abilities:posts:write.

Respons Rapi dengan API Resource

Mengembalikan model mentah sebagai JSON memang praktis, tetapi semua kolom ikut terkirim dan format respons berubah setiap kali struktur tabel berubah. API Resource menjadi lapisan penerjemah di antara model dan respons. Buat kelasnya dengan php artisan make:resource PostResource, lalu tentukan field yang ingin Anda kirim di method toArray().

Di controller, kembalikan daftar artikel dengan return PostResource::collection(Post::with('user')->paginate(15));. Laravel membungkus data dalam kunci data dan menambahkan links serta meta yang berisi informasi halaman. Perhatikan with('user'): tanpa eager loading, resource yang menampilkan nama penulis akan memicu masalah yang kita bahas di artikel Eloquent relationship dan N+1 query.

Di dalam resource, gunakan $this->whenLoaded('user') agar relasi hanya tampil bila memang sudah termuat. Laravel 13 juga menyediakan resource yang mengikuti spesifikasi JSON:API lewat php artisan make:resource PostResource --json-api. Pilihan ini berguna bila klien Anda mengharapkan format tersebut.

Membatasi Jumlah Permintaan

Grup middleware api tidak memasang pembatas laju secara bawaan, padahal endpoint seperti login rawan menjadi sasaran tebakan password berulang kali. Definisikan limiter di method boot milik AppServiceProvider: RateLimiter::for('api', fn (Request $request) => Limit::perMinute(60)->by($request->user()?->id ?: $request->ip()));

Pasang limiter itu dengan middleware throttle:api pada rute atau grup rute. Endpoint login memerlukan limiter terpisah yang jauh lebih ketat, misalnya lima percobaan per menit. Klien yang melewati batas akan menerima status 429 Too Many Requests.

Menguji dengan curl atau Postman

Jalankan server lokal dengan php artisan serve, lalu minta token lewat terminal:

curl -X POST http://127.0.0.1:8000/api/login -H "Accept: application/json" -d "email=budi@example.com" -d "password=rahasia123" -d "device_name=laptop"

Salin token dari respons, lalu panggil endpoint yang terlindungi:

curl http://127.0.0.1:8000/api/posts -H "Accept: application/json" -H "Authorization: Bearer TOKEN_ANDA"

Header Accept: application/json penting. Tanpa header itu, Laravel bisa mengarahkan permintaan yang gagal autentikasi ke halaman login alih-alih membalasnya dengan status 401 berformat JSON.

Di Windows PowerShell 5.1, ketik curl.exe karena curl di sana merupakan alias untuk Invoke-WebRequest. Jika Anda lebih suka antarmuka grafis, Postman bisa melakukan hal yang sama: pilih tipe Bearer Token di tab Authorization, lalu tambahkan header Accept.

Langkah Berikutnya

Secara bawaan, token Sanctum tidak pernah kedaluwarsa. Di aplikasi produksi, atur masa berlakunya lewat opsi expiration di config/sanctum.php. Setelah itu, jadwalkan php artisan sanctum:prune-expired --hours=24 untuk membersihkan token yang sudah lama kedaluwarsa.

Selanjutnya, lengkapi API dengan pengujian otomatis memakai Sanctum::actingAs(), dokumentasikan setiap endpoint, dan pastikan seluruh lalu lintas berjalan lewat HTTPS. Rujukan lengkapnya ada di dokumentasi Laravel Sanctum.
