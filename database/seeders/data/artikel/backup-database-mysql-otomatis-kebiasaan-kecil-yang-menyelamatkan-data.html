Disk rusak, server diretas, atau salah menjalankan DELETE tanpa WHERE: kehilangan data jarang datang dengan pemberitahuan. Pada toko daring atau sistem kasir UMKM, hilangnya data transaksi seminggu saja bisa berarti hilangnya catatan penjualan sekaligus kepercayaan pelanggan.

Kabar baiknya, Anda bisa menyiapkan pencadangan (backup) otomatis MySQL dalam satu sore. Artikel ini membahas cara membuat dump yang konsisten dengan mysqldump, menyimpan kredensial dengan aman, dan menjadwalkan pencadangan di Linux maupun Windows. Setelah itu, kita akan membahas cara mengatur masa simpan, menyimpan salinan di luar server, dan menguji pemulihan.

Membuat Dump yang Konsisten dengan mysqldump

Program mysqldump menghasilkan berkas yang berisi perintah SQL. Anda bisa menjalankan ulang perintah itu untuk membangun kembali basis data. Opsi terpentingnya adalah --single-transaction. Opsi ini memulai transaksi sebelum membaca data sehingga hasil dump mencerminkan kondisi basis data pada satu titik waktu tanpa mengunci tabel dan tanpa menghentikan aplikasi.

Ada dua catatan penting. Pertama, konsistensi itu hanya berlaku untuk tabel InnoDB. Kedua, selama dump berjalan, jangan jalankan perintah seperti ALTER TABLE atau TRUNCATE TABLE pada tabel yang sedang Anda cadangkan karena hasilnya bisa keliru atau gagal.

Berikut contoh perintah lengkap di Linux yang sekaligus mengompresi hasil dump dengan gzip agar ukuran berkasnya jauh lebih kecil:

mysqldump --defaults-extra-file=/etc/mysql/backup.cnf --single-transaction --routines --events toko_db | gzip > /var/backups/mysql/toko_db-$(date +%F).sql.gz

Perintah di atas memuat opsi --routines dan --events karena stored procedure, function, dan event tidak ikut secara bawaan, sedangkan trigger sudah ikut otomatis. Bagian $(date +%F) menghasilkan tanggal seperti 2026-07-02 sehingga setiap berkas memiliki nama unik per hari.

Jangan Tulis Password di Baris Perintah

Menulis password langsung di perintah, misalnya -pRahasia123, memang praktis, tetapi berisiko. Di beberapa sistem, pengguna lain bisa melihat perintah yang sedang berjalan lewat program seperti ps. Perintah itu juga bisa tersimpan di riwayat shell.

Simpan kredensial di option file. Buat berkas /etc/mysql/backup.cnf yang berisi bagian [client] dengan baris user dan password, lalu batasi aksesnya dengan chmod 600 /etc/mysql/backup.cnf agar hanya pemiliknya yang bisa membacanya. Opsi --defaults-extra-file harus berada di depan opsi lain, seperti pada contoh di atas.

Gunakan juga akun MySQL khusus pencadangan, bukan root. Setelah membuat akun itu dengan CREATE USER, berikan hanya hak yang cukup untuk mysqldump, tanpa hak menulis: GRANT SELECT, SHOW VIEW, TRIGGER, EVENT, PROCESS ON *.* TO 'pencadang'@'localhost';. Dengan demikian, berkas kredensial yang bocor tidak memberi akses untuk mengubah atau menghapus isi tabel.

Menjadwalkan Pencadangan Otomatis

Linux dengan cron

Simpan perintah mysqldump di atas dalam skrip bash, misalnya /usr/local/bin/backup-mysql.sh, lalu awali isinya dengan set -o pipefail. Tanpa opsi itu, kegagalan mysqldump bisa tertutupi karena gzip tetap selesai dengan sukses. Akibatnya, skrip meninggalkan berkas yang tampak normal, padahal isinya kosong atau terpotong.

Jadwalkan skrip itu lewat crontab -e dengan baris 30 1 * * * /usr/local/bin/backup-mysql.sh agar pencadangan berjalan setiap hari pukul 01.30. Menaruh perintah di skrip juga menghindarkan Anda dari jebakan crontab: cron memperlakukan tanda % di baris crontab sebagai baris baru sehingga $(date +%F) yang Anda tulis langsung di sana tidak berjalan sesuai harapan.

Windows dengan Task Scheduler

Di Windows, simpan perintahnya dalam berkas skrip, misalnya C:\backup\backup-mysql.bat, dan tulis jalur lengkap ke mysqldump.exe karena tugas terjadwal belum tentu memakai PATH yang sama dengan terminal Anda. Gunakan opsi --result-file untuk menulis hasil dump, bukan tanda >. Dokumentasi MySQL mengingatkan bahwa pengalihan keluaran di PowerShell menghasilkan berkas UTF-16 yang tidak bisa Anda pulihkan dengan benar.

Daftarkan skripnya dengan schtasks /create /tn "Backup MySQL" /tr C:\backup\backup-mysql.bat /sc daily /st 01:30, atau lewat menu Create Basic Task di aplikasi Task Scheduler. Pada properti tugas, pilih Run whether user is logged on or not agar pencadangan tetap berjalan meskipun tidak ada pengguna yang masuk ke Windows.

Atur Masa Simpan dan Simpan Salinan di Luar Server

Cadangan harian yang tidak pernah Anda hapus lama-kelamaan akan memenuhi disk. Tentukan masa simpan, misalnya 14 hari, lalu tambahkan baris berikut di akhir skrip Linux: find /var/backups/mysql -name "*.sql.gz" -mtime +14 -delete. Anda juga bisa memakai pola berjenjang yang lazim, misalnya menyimpan cadangan harian selama dua minggu, mingguan selama dua bulan, dan bulanan selama setahun.

Yang tidak kalah penting, cadangan yang hanya tersimpan di server yang sama akan ikut hilang bila server itu rusak atau terkena serangan peretas. Terapkan aturan 3-2-1 berikut:

  • Tiga salinan data, yaitu data asli dan dua cadangan.

  • Dua jenis media atau tempat penyimpanan yang berbeda, misalnya disk server dan object storage.

  • Satu salinan di luar lokasi utama, misalnya di layanan cloud atau server di kota lain.

Alat seperti rclone atau rsync bisa menyalin berkas cadangan ke lokasi lain secara otomatis setelah dump selesai. Bila basis data berisi data pribadi pelanggan, enkripsi dulu berkasnya sebelum mengunggahnya.

Uji Pemulihan secara Berkala

Cadangan yang belum pernah Anda coba pulihkan belum layak disebut cadangan. Jadwalkan uji pemulihan, misalnya sebulan sekali, ke basis data terpisah dengan langkah berikut:

  1. Buat basis data kosong khusus uji, misalnya toko_db_uji.

  2. Pulihkan berkas terbaru dengan gunzip < toko_db-2026-07-01.sql.gz | mysql -u root -p toko_db_uji.

  3. Bandingkan jumlah baris tabel penting, misalnya pesanan dan pelanggan, dengan basis data produksi.

  4. Catat lama proses pemulihan agar Anda tahu perkiraan waktu henti bila bencana benar-benar terjadi.

Lirik MySQL Shell untuk Basis Data Besar

Program mysqldump nyaman untuk basis data kecil hingga menengah. Namun, dokumentasi resminya sendiri menyebut bahwa alat ini tidak dirancang untuk mencadangkan data berukuran besar. Pemulihannya bisa sangat lambat karena MySQL harus menjalankan ulang setiap perintah SQL.

Alternatifnya adalah utilitas dump di MySQL Shell. Perintah seperti util.dumpSchemas(["toko_db"], "/var/backups/mysql/toko_db-dump") menjalankan dump paralel dengan beberapa thread, mengompresi berkas secara bawaan, dan menampilkan progres. Pemulihannya memakai util.loadDump(). Bila data Anda jauh lebih besar lagi, pertimbangkan pencadangan fisik yang menyalin berkas data secara langsung.

Mulai Hari Ini

Pencadangan otomatis adalah kebiasaan kecil yang nilainya baru terasa saat musibah datang. Mulailah dari yang sederhana: satu skrip mysqldump dengan --single-transaction, kredensial di option file, jadwal harian, masa simpan yang jelas, dan setidaknya satu salinan di luar server.

Setelah itu, jadikan uji pemulihan sebagai agenda rutin, bukan kegiatan saat panik. Anda bisa memeriksa rincian setiap opsi di dokumentasi mysqldump.
